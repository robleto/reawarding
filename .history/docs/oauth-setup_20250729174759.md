
# OAuth Setup Guide for Reawarding Authentication

## Overview

The authentication system now supports three OAuth providers:

- **GitHub** (already configured)
- **Google** (needs configuration)
- **Facebook** (needs configuration)

## Current Implementation Status

- ✅ **UI Updates Complete**: Both LoginModal and SignupModal now display buttons for Google, Facebook, and GitHub OAuth.
- ✅ **Code Integration Complete**: OAuth handlers in both modals support all three providers.
- ⚠️ **Supabase Configuration Required**: Google and Facebook providers need to be configured in your Supabase project.

## Supabase OAuth Configuration

To enable Google and Facebook OAuth, you'll need to configure these providers in your Supabase project dashboard:

### 1. Access Supabase Dashboard

1. Go to [https://supabase.com/dashboard](https://supabase.com/dashboard)
2. Select your project: `cjrpnzwrldlxajkvznca`
3. Navigate to **Authentication** → **Providers**

### 2. Configure Google OAuth

#### Create Google OAuth App

1. Go to [Google Cloud Console](https://console.cloud.google.com/)
2. Create a new project or select an existing one
3. Enable Google+ API
4. Go to **APIs & Services** → **Credentials**
5. Create **OAuth 2.0 Client ID**
6. Set **Application type** to **Web application**
7. Add **Authorized redirect URIs**:
   - Development: `https://cjrpnzwrldlxajkvznca.supabase.co/auth/v1/callback`

#### Configure in Supabase 

1. In Supabase dashboard, go to **Authentication** → **Providers**
2. Find **Google** and click **Enable**
3. Enter your **Client ID** and **Client Secret** from Google Cloud Console
4. Set **Redirect URL** to: `https://cjrpnzwrldlxajkvznca.supabase.co/auth/v1/callback`

### 3. Configure Facebook OAuth

#### Create Facebook App

1. Go to [Facebook Developers](https://developers.facebook.com/)
2. Create a new app or select an existing one
3. Add **Facebook Login** product
4. In **Facebook Login** → **Settings**:
   - Add **Valid OAuth Redirect URIs**:
     - `https://cjrpnzwrldlxajkvznca.supabase.co/auth/v1/callback`

#### Configure in Supabase

1. In Supabase dashboard, go to **Authentication** → **Providers**
2. Find **Facebook** and click **Enable**
3. Enter your **App ID** and **App Secret** from Facebook Developers
4. Set **Redirect URL** to: `https://cjrpnzwrldlxajkvznca.supabase.co/auth/v1/callback`

## Environment Variables

Add the following to your `.env.local` file (optional, for reference):

```bash
# Google OAuth (configured in Supabase dashboard)
# GOOGLE_CLIENT_ID=your_google_client_id
# GOOGLE_CLIENT_SECRET=your_google_client_secret

# Facebook OAuth (configured in Supabase dashboard)
# FACEBOOK_APP_ID=your_facebook_app_id
# FACEBOOK_APP_SECRET=your_facebook_app_secret
```

## Testing OAuth Integration

### Testing Steps

1. Start the development server: `npm run dev`
2. Open [http://localhost:3001](http://localhost:3001)

### Expected Behavior

- **Before Configuration**: Google and Facebook buttons will show an error message when clicked
- **After Configuration**: All three providers should redirect to their respective OAuth flows

## Error Handling

The current implementation includes error handling for OAuth failures:

- Errors are displayed in the modal
- Users can still use email/password authentication
- Loading states prevent multiple clicks during OAuth redirect

## Next Steps

### Common Issues

1. **"Provider not enabled"**: Configure the provider in Supabase dashboard
2. **"Invalid redirect URI"**: Ensure redirect URIs match exactly in OAuth app settings
3. **"OAuth application not found"**: Check Client ID/App ID is correct
4. **Development vs Production**: Make sure to add both development and production redirect URIs
5. **Test all three providers** in development
6. **Update production redirect URLs** when deploying

### Debug Steps

1. Check browser console for error messages
2. Verify OAuth provider configuration in Supabase
3. Ensure redirect URIs are correctly set
4. Test with a different browser/incognito mode

## Benefits of Multiple OAuth Providers

Adding Google and Facebook OAuth provides:

- **Better User Experience**: Users can choose their preferred login method
- **Higher Conversion**: Reduced friction for users who prefer social login
- **Reliability**: Fallback options if one provider has issues
- **Accessibility**: Some users may not have GitHub accounts
